# Бот и сервер очков «Прыг-Скок»

Node.js + [grammY](https://grammy.dev). Один процесс делает две вещи:

- **бот**: на `/start` присылает кнопку «Играть» (игра открывается как Telegram Mini App),
  `/top` показывает таблицу рекордов, `/me` — рекорд, место и достижения игрока,
  а о новых достижениях бот пишет в личку;
- **сервер очков**: принимает результаты уровней и игр, хранит их в SQLite (`scores.db`),
  считает таблицу рекордов и 12 достижений (список в `achievements.js`).

Игрок определяется по подписи Telegram (`initData`), которую сервер проверяет токеном бота,
поэтому записать очки за другого человека нельзя. Сами очки считает игра на телефоне,
так что от опытного читера это не защищает; сервер лишь отбрасывает явно невозможные значения.

## Запуск

1. Node.js 22.13 или новее (подойдёт текущая LTS с nodejs.org).
2. `cp .env.example .env` и впишите в `.env` токен от @BotFather (`BOT_TOKEN`). Остальное можно не менять.
3. Поставьте **cloudflared** — он бесплатно даёт серверу https-адрес, без регистрации:
   - Windows: `winget install --id Cloudflare.cloudflared` (после установки откройте новое окно терминала);
   - macOS: `brew install cloudflared`;
   - Linux: пакет с https://github.com/cloudflare/cloudflared/releases
4. `npm install`
5. `npm start`

В консоли появятся строки «Туннель: https://…trycloudflare.com» и «Бот @… запущен».
Адрес туннеля меняется при каждом запуске, бот сам передаёт его игре через кнопку «Играть»,
поэтому после перезапуска бота откройте игру заново кнопкой из чата.

Без cloudflared бот тоже работает, но игра не сможет сохранять очки (кнопки «Рекорды» не будет).

Файл `.env` в git не попадает. Никогда не публикуйте токен; если он где-то засветился,
получите новый в @BotFather командой `/revoke`.

## Где держать бота круглосуточно

Бот и сервер работают, пока запущен процесс. Для работы 24/7 нужен компьютер, который не выключается:

- **Чистый VPS на Ubuntu/Debian** (от ~200 ₽/мес): скрипт ставит Node.js и cloudflared
  (оба с проверкой контрольных сумм), код и службу systemd в песочнице с лимитом памяти.
  Перед установкой он прогоняет тесты бота. Токен спросит при первом запуске:
  ```sh
  curl -fsSLo install.sh https://raw.githubusercontent.com/admin2vitaplus/tg-mario/main/bot/deploy/install.sh
  less install.sh        # прочитайте, что он делает
  sudo bash install.sh
  ```
  Если на сервере бот уже запущен по-другому, скрипт откажется ставить второй: два бота
  с одним токеном мешают друг другу. Повторный запуск обновляет эту же установку.
  Логи: `journalctl -u prygskok-bot -f`, база: `/opt/tg-mario/data/scores.db`.
  Служба ограничена по памяти (300 МБ) и процессору (`CPU_QUOTA`, по умолчанию 50% одного ядра).
  Перед перезапуском скрипт прогоняет `npm test` от пользователя службы, но вне песочницы systemd.
  Свой домен с https вместо туннеля: `sudo PUBLIC_API_URL=https://ваш.домен bash install.sh`.
- **Railway / Render / Fly.io**: корень сервиса — папка `bot`, команда запуска `npm start`,
  переменные `BOT_TOKEN` и `TUNNEL=off` задаются в настройках сервиса, а `PUBLIC_API_URL` —
  адрес, который выдаст платформа. Для базы нужен постоянный диск (volume), иначе очки
  сотрутся при перезапуске; путь к файлу задаётся в `DB_FILE`.

## Постоянный адрес сервера

Бесплатный туннель получает новый адрес при каждом перезапуске бота. Бот сам обновляет
кнопку меню и кнопку «Играть», а игра, открытая по старой ссылке, показывает «сервер переехал»
и предлагает открыть её заново. Если туннель падает сам, бот завершается, и systemd поднимает
его вместе с новым туннелем.

Чтобы адрес не менялся вообще, задайте `PUBLIC_API_URL` и выключите туннель (`TUNNEL=off`).
Два способа:

- **Без домена и регистрации** (нужен постоянный IP и открытые порты 80 и 443):
  Caddy сам получает сертификат Let's Encrypt для имени вида `1-2-3-4.sslip.io`,
  которое указывает на IP сервера.
  ```sh
  sudo apt install -y caddy
  IP=$(curl -fsS https://api.ipify.org); HOST="${IP//./-}.sslip.io"
  printf '%s {\n  reverse_proxy 127.0.0.1:8080\n}\n' "$HOST" | sudo tee /etc/caddy/Caddyfile
  sudo systemctl reload caddy
  echo "PUBLIC_API_URL=https://$HOST"   # впишите в .env бота вместе с TUNNEL=off
  ```
  WebSocket «Танков» Caddy проксирует сам. Если сертификат не выдаётся (лимиты Let's Encrypt
  для sslip.io), используйте свой домен.
- **Свой домен**: A-запись на IP сервера и тот же Caddyfile с вашим именем, либо именованный
  туннель Cloudflare (`cloudflared tunnel create`, домен должен быть в Cloudflare).

## Сервер для других игр

HTTP-сервер общий (`server.js`), маршруты «Прыг-Скока» живут под `/api/mario/`.
Другая игра добавляет свои маршруты рядом (`/api/<игра>/…`) и использует ту же проверку игрока
(`verifyInitData` из `auth.js`).

Сетевой «Танкодром» подключён к этому же серверу: комнаты на двоих работают по WebSocket
на пути `/ws/tanks` (`tanks-rooms.js`), через тот же туннель. Приглашение через бота:
ссылка `https://t.me/<бот>?start=room_123456` присылает кнопку, которая открывает комнату 123456.
Сама игра зовёт друга ссылкой `https://t.me/<бот>?startapp=room_123456__<имя-туннеля>`: она открывает
Main Mini App (адрес задаётся в BotFather) сразу в комнате. После `__` идёт имя туннеля
(`<имя>.trycloudflare.com`), потому что у такой ссылки нет `?api=`. Статистика эту часть отбрасывает.

Защита комнат (`LIMITS` в `tanks-rooms.js`): проверка `Origin`, сообщение не больше 16 КБ,
не больше 3 соединений на игрока Telegram (`?auth=<initData>`) и 8 на адрес, 3 открытые комнаты
на адрес, коды из 6 цифр и не больше 10 неудачных попыток войти в минуту, молчащее 90 с
соединение закрывается (игра шлёт `ping` раз в 20 с). Если у игрока оборвалась связь, его место
держится 20 с (хозяину, который ещё ждёт гостя, — 2 минуты), он возвращается по токену комнаты;
второй игрок в это время видит «ждём». Пустая комната закрывается через 10 минут.

## Статистика

Команда `/stats` в боте показывает игроков по дням и неделям, новых по источникам, K-фактор,
удержание дня 1 и дня 7, матчи по дням и цифры по каждой игре. Доступна только Telegram id из
`ADMIN_ID` (через запятую); пока переменная пуста, команда выключена.

- Источник игрока — метка из ссылки: `t.me/<бот>?start=src_<метка>` (реклама, канал),
  `?start=ref_<id>` (личное приглашение, его выдаёт `/invite`), `?start=room_<код>` или
  `tanks_<код>` (комната «Танкодрома»). Для Mini App то же самое в `startapp=`.
- K-фактор = новые игроки, пришедшие по приглашениям ÷ игроки, отправившие приглашение.
- Игры шлют события через `web/lib/events.js`: `GameEvents.send('game_start', 'tanks')`,
  `GameEvents.send('match_finished', 'tanks', '<код комнаты>')` и т. д. (`POST /api/events`).
- Хранятся только Telegram id и метки. Сырые события старше 90 дней сворачиваются в суммы
  по дням (`stats_daily`) и удаляются.

## Жетоны

Игровая валюта (ТЗ P1-7, `economy.js`). Все суммы — в `economy.json`, меняются только через PR
(тест `test/economy.test.js` проверяет, что призы по местам в сумме равны фонду недели).

- **Начисляет только сервер** и только за то, что он сам проверил: достижения «Прыг-Скока»
  (разово), личный рекорд (раз в день), первая принятая игра за день с серией дней, приглашение
  (`/invite`) — когда новичок сам доиграл `invite.gamesNeeded` игр, обоим; итоги недели — призы
  за места в таблице рекордов «Прыг-Скока» за неделю и в общем зачёте (жетоны за неделю).
  «Танкодром» пока не присылает серверу проверяемых результатов, поэтому жетонов за него нет.
- **Потолки**: не больше `dailyCap` в день на игрока (всё, кроме призов недели); фонд недели
  `season.pool`. Максимум за неделю при N игроках: `dailyCap × 7 × N + pool` (сейчас 1050 × N + 2000).
- **Журнал** `ledger` — только добавление (UPDATE и DELETE запрещены триггерами), целые числа;
  одно событие начисляет один раз: `UNIQUE (игрок, причина, событие)`. Баланс — сумма журнала,
  `wallets.balance` — его кэш, обновляется в той же транзакции.
- **Сезон = неделя** с понедельника 00:00 UTC. Бот закрывает прошедшие недели при запуске и
  каждые 10 минут: снимок балансов и мест → призы → сообщение игрокам с итогами (кнопка
  «Не присылать итоги», включить снова — `/weekly`; выключить всем — `season.notify: false`).
  Каждый шаг — своя транзакция, перезапуск посередине продолжает с того же места.
- **Экспорт**: `npm run export:season -- <номер сезона> [файл.csv]` (без номера — прошлая неделя)
  пишет `player_id,amount,balance` и сверяет сумму по файлу с журналом. База берётся из `DB_FILE`.
  Номер текущего сезона виден в `/stats`.
- **Магазин**: товары в `economy.json` (`shop`), в игре они помечены `shop: '<id>'` в «Внешнем виде».
- **Защита**: игрок, у которого за день `suspicious.rejectedPerDay` отчётов отклонены как невозможные,
  помечается: начисления и призы ему не идут. Команды для `ADMIN_ID`: `/wallet <id>` — баланс и
  операции, `/flag <id> [причина]`, `/unflag <id>`, `/annul <id> [сезон]` — снять всё полученное за
  сезон одной отрицательной записью. В `/stats` — выдача за неделю, доли по причинам, топ получателей.
- API для игры: `GET /api/wallet/info` (правила и магазин), `GET /api/wallet/me`,
  `POST /api/wallet/buy {item}`; итоги уровня и игры возвращают `wallet: { grants, balance }`.

## Для сервера

- `GET /api/health` → `{"ok":true,"commit":"<sha>","uptime":<сек>}`. Коммит берётся из
  `GIT_COMMIT`, из файла `bot/.commit` (его может записать автообновлятор) или из git.
- Схема базы обновляется сама при запуске, только вперёд (`PRAGMA user_version`,
  список миграций в `db.js`). Новые миграции добавляются в конец списка, старые не меняются.
- По `SIGTERM` бот останавливает опрос Telegram, закрывает HTTP и WebSocket, туннель и базу.
- В логи не попадают токен, `initData` и подписи Telegram (`log.js`).

## Проверка

`npm test` — тесты API: подпись Telegram, запись результатов, достижения, таблица рекордов.
